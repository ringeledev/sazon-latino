Features

Everything the restaurant runs on

Built around the real day-to-day of the team: fast during service, clear for the owner at the end of the day.

🪑

Table management

Free/occupied status, table details, add items to an open order at any time.

📋

Orders

Create and edit orders, see their details and status, add items after the first round.

👨‍🍳

Kitchen view

A dedicated screen with incoming orders for the kitchen team.

📖

Menu management

Products and categories with prices, ordered logically (drinks, starters, mains…).

👥

Users & roles

Admin and waiter roles, PIN login, staff activation and colour identifiers.

📊

Dashboard & reports

Revenue, average ticket, sales by category and product, per-waiter performance, order history.

📤

Excel export

Export the orders of any period to Excel for accounting.

🖨️

Thermal printing

Kitchen and bar tickets and receipts on Epson TM-T88V printers, plus cash drawer opening.

Architecture

Web app + cloud database + local print server

Browsers can't talk to USB printers directly, so I built a small local Node.js service that receives print jobs over HTTP and sends raw ESC/POS commands to the printers.

Real-world problems

What I learned building it

  • Hardware integration — talking to thermal printers and a cash drawer with raw ESC/POS commands.
  • Data correctness — SQL scripts to route drinks to the bar and clean up orphan orders.
  • Real users — designing for waiters working fast during service, on shared tablets.
  • Business reporting — turning orders into revenue, average ticket and per-waiter metrics.
  • AI-assisted development — using Lovable and Claude to build, debug and document faster.
